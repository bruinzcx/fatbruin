## 需求由来

某医药行业客户（日本）反馈：代表在家录制 AI 作业，家庭环境入镜有隐私顾虑。诉求是类似腾讯会议的背景虚化——录制时模糊背景，只保留人像区域清晰。

## 三输入滤镜：业界通用解法

整条链路业界方案高度一致，三步：

1. **背景**：对视频帧做高斯模糊，得到「模糊帧」。
2. **抠图**：实时对每帧做**人像分割**，产出黑白灰度图（mask）——人像白、背景黑。
3. **合成**：自定义**三输入滤镜**，喂进「模糊帧 + mask + 原始帧」，在片元着色器里逐像素遴选：mask 白取原始帧，黑取模糊帧。

视频帧处理复用项目已引入的 **GPUImage**。核心是一个 `GPUImageThreeInputFilter` 子类：

```glsl
vec4 baseColor = texture2D(inputImageTexture, textureCoordinate);      // 原始帧
vec4 blurredColor = texture2D(inputImageTexture2, textureCoordinate2); // 模糊帧
vec4 maskColor = texture2D(inputImageTexture3, textureCoordinate3);    // mask

// 预乘 Alpha
baseColor.rgb *= baseColor.a;
blurredColor.rgb *= blurredColor.a;

// mask 取灰度值，smoothstep 平滑边界
float maskValue = dot(maskColor.rgb, vec3(0.299, 0.587, 0.114));
float smoothMaskValue = smoothstep(0.0, 1.0, maskValue);

vec4 mixedColor = mix(blurredColor, baseColor, smoothMaskValue);

// 解除预乘 Alpha
if (mixedColor.a > 0.0) { mixedColor.rgb /= mixedColor.a; }
gl_FragColor = mixedColor;
```

滤镜链装配：`GPUImageGaussianBlurFilter`（半径 31px）接到三输入滤镜的 texture 1，mask 走「腐蚀 → 高斯模糊」后接 texture 2。

**关键判断**：整个方案的难点不在渲染（滤镜合成耗时实测仅 4ms，优化空间极小），而在**人像分割推理**。渲染是确定成本，推理是变量成本。

## 两条分割路线

### 路线 A：自研 TFLite 模型

AI 组提供基于 `TensorFlowLiteObjC` 的深度学习分割模型，两个尺寸：

| 模型 | 输入尺寸 |
|------|----------|
| `128x128_fp32.tflite` | 128×128 |
| `256x144_fp32.tflite` | 256×144 |

端上处理流程：`CMSampleBuffer` → OpenCV `cv::Mat` → 按 orientation/镜像翻转 → 缩放到模型尺寸（**该模型无需等比缩放，可直接拉伸变形推理，结果再反向拉伸**）→ 归一化 float32 → `TFLInterpreter` 推理 → 输出解析为 `CV_8UC1` mask → 放大回原始尺寸。

> ⚠️ **素材自承的缺陷**（raw 内代码注释已标注，wiki 沿用不改 raw）：输出解析用 `out_mask.data[i] = (output[2*i+1] > 0.1f) ? 255 : 0;` 做二值化，但模型实际输出是概率分布而非非 0 即 1。硬阈值二值化正是下面「边缘锯齿」问题的根因之一。

### 路线 B：Apple Vision 框架

Vision 是 Apple WWDC 2017 推出的图像识别框架，自带一批训练好的 Core ML 模型。人像分割对应 `VNGeneratePersonSegmentationRequest`，**要求 iOS 15.0+**。

```objectivec
VNGeneratePersonSegmentationRequest *request = [[VNGeneratePersonSegmentationRequest alloc] init];
request.qualityLevel = VNGeneratePersonSegmentationRequestQualityLevelAccurate; // 或 Balanced / Fast
request.outputPixelFormat = kCVPixelFormatType_OneComponent8;

VNImageRequestHandler *handler = [[VNImageRequestHandler alloc] initWithCVPixelBuffer:pixelBuffer options:@{}];
[handler performRequests:@[request] error:&error];

VNPixelBufferObservation *mask = (VNPixelBufferObservation *)request.results.firstObject;
// mask.pixelBuffer → CIImage → CGImage → UIImage → 前置摄像头需垂直翻转 → 送入滤镜
```

**Vision 的两个约束**：
- 项目最低支持 iOS 10.0，Vision 路线天然覆盖不全，必须保留降级分支。
- `Accurate` 档速度偏慢；`Balanced` 档效果当时未经产品验证。

**最终选择**：采用 `Balanced` 档做工程化，效果可接受。

## 端侧四项优化

这四项是 APP 侧在模型能力不变的前提下能拿到的全部增益。

### 1. 边缘高斯模糊（治锯齿）

模型 mask 黑白分界锐利（像素非 1 即 0），视觉上人像与背景交界有明显落差。做法：mask 进片元着色器**之前**先过一次 7px 高斯模糊，抹平锋利边缘。

代价：人像周围出现一圈半透明光圈。**光圈半径取决于 mask 图尺寸**——mask 越大越精细，光圈越小越贴合真实人像（小图放大出马赛克，同一原理）。这条把「模型分辨率」和「视觉质量」直接绑定了。

### 2. 边缘腐蚀（治背景漏出）

边缘模糊后，半透明光圈会漏出背景信息。做法：高斯模糊**之前**先对 mask 做 3px 腐蚀，人像区域向内收缩。

### 3. 插值优化（治帧率）

结合 AI 作业录制场景（人基本不动，只有面部口型变化），两帧差异小于阈值就跳过推理，直接复用上一帧结果。

> ⚠️ **素材内表述不一致**（未改 raw）：正文写「两帧之间变化不超过 96.5% 的不再执行推理」，语义与代码 `threshold:0.035` 相反——实际逻辑应为「差异 < 3.5% 则跳过」。且「优化方向」一节又给出 2.5% 基准。以代码为准，阈值口径以 3.5% 与 2.5% 两组实测数据并存理解。

差值计算本身有成本（实测 5ms）。这是笔条件期望的账：**跳过时净赚一次推理（27ms），未跳过时净亏 5ms**。只有当差值计算成本远小于推理成本时才划算——27ms vs 5ms，成立。

### 4. 帧缓存（治闪帧）

推理可能报错。每帧推理成功后缓存结果，当前帧失败则沿用上一帧 mask。**目的不是性能，是隐私安全**——避免模糊失效瞬间暴露完整背景。

## 性能实测（iPhone 11 / iOS 15.2 / Vision Balanced）

| 环节 | 耗时 |
|------|------|
| 人像分割推理 | 27.1 ms |
| mask 转图片 | 8.5 ms |
| 滤镜合成 + 边缘优化 | 4 ms |
| 差值计算 | 5 ms |
| **人像分割总增量** | **约 35 ms/帧** |

- 不开人像分割：跑满 30 FPS（每帧预算 33.3ms）。
- 开背景模糊：降至 10–15 FPS（每帧 66.67ms）。
- 开插值优化（2.5% 基准）+ 人像动作幅度小：回升到 20–25 FPS。

35ms 的增量直接吃掉 30FPS 的整个帧预算——这就是帧率腰斩的算术根源。插值优化本质是把「每帧都推理」摊薄成「变化帧才推理」。

## 遗留问题

- **手指被腐蚀掉**：手指区域本就识别偏细，向内腐蚀 3px 后直接消失。腐蚀是治背景漏出的代价，两者互斥。
- **帧率低**：背景模糊与人脸美颜两条滤镜链同时跑，性能不足。
- **精度不足**：当前模型尺寸小，换高精度模型进一步压帧率，视频卡顿。
- **插值残影**：插值基准越大帧率提升越明显，但人像分割效果劣化，出现残影。

## 优化方向

**AI 侧**：提升模型运算效率与推理精度（AI 团队负责）。

**APP 侧**：
- 若模型精度提升，移除腐蚀逻辑，保住人像完整性。
- 检测多滤镜链合并时的效率，决定是否拆分美颜与背景模糊。
- 用帧采样做 mask 基准，进一步降低推理次数。
- 备多个模型，**按实时帧率动态降级**。
